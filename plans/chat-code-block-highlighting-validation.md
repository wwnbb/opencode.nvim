# Проверка подсветки блоков кода

Реализовано по [плану](chat-code-block-highlighting.md). Дата: 2026-09-22.
Среда: Neovim `v0.12.0-dev-2149+ga60d5f863e`, macOS, реальные NuiLine/extmarks,
Lua parser из runtime и установленный Rust parser с highlight queries.

## Подтверждённое поведение

| Требование | Проверка |
| --- | --- |
| Общий разбор fences, длина/тип ограждения, отступы, незакрытый блок | `tests/unit/code_blocks_spec.lua`: 4 теста |
| Байтовая проекция, многострочные captures, переносы и скрытые строки | `tests/unit/syntax_projection_spec.lua`: 2 теста; `chat_code_highlights_spec.lua` на настоящем Lua parser |
| User/assistant/local notices, короткие блоки, CRLF, Unicode и табы | Unit renderer checks и `tests/integration/chat_code_stream_spec.lua` |
| Незакрытый блок во время busy session, строка/комментарий/ограждение по частям | Integration-spec проверяет реальные extmarks на каждом снимке до завершения ответа |
| Живой и полный рендер совпадают, включая соседние виджеты | Integration-spec сравнивает строки и нормализованные координаты/группы; ID extmarks исключены |
| Closing fence не окрашивает последующий текст; authoritative replacement удаляет старые отметки | Integration-spec и TCP/SSE smoke |
| Остановка генерации, окончание без closing fence, reopen и переключение сессии | Integration-spec проверяет сохранение подсветки и отсутствие изменений чужого буфера |
| Лимиты, отключение подсветки, тема, восстановление после недоступного parser | Unit и integration checks, включая отсутствие отрицательного результата в кеше готовых строк |
| Кеш не зависит от ширины и не растёт с каждой delta | Unit checks, ограничение 128 записей/8 МиБ; native timing fixture считает вызовы parser |
| Координаты query directives сохранены после оптимизации | Отдельный тест `#offset!` с ожидаемыми байтовыми границами |
| Фон и читаемость, тёмная/светлая тема, узкий/широкий чат, фокус/черновик/курсор | Native Neovim line-grid fixture и просмотр снимков |

## Прогоны

Все команды завершились успешно:

- `./tests/run.sh unit`: 285 успешных тестов в полном прогоне.
- `./tests/run.sh checks`: 24 успешных теста.
- `./tests/run.sh integration`: 10 успешных тестов.
- `./tests/run.sh smoke`: 3 успешных spec, содержащих также проверки существующих виджетов.
- После добавления отдельной проверки query directive повторно выполнен `./tests/run.sh tests/unit/chat_code_highlights_spec.lua`: все 7 тестов успешны. Этот файл содержал 6 тестов в полном unit-прогоне; production-код после него не менялся.

Тест транспорта требует локального TCP-listener. Первый запуск внутри песочницы
получил `EPERM`; отдельная проверка транспорта и финальный полный unit-прогон
прошли с доступом к локальным сокетам.

## Настоящий SSE и визуальная проверка

`tests/runtime/run_code_highlights.py` запускает настоящий Neovim с подключённым
line-grid UI, затем локальный HTTP/SSE-сервер. Сервер отдаёт v2 events по
`/api/event`; они проходят через TCP transport, SSE decoder, v2 reducer,
render coordinator и chat buffer. Модель и внешний аккаунт не используются.

Сервер приостанавливает поток перед closing fence. Neovim подтверждает наличие
полученного текста и синтаксических extmarks, пока `text.ended` ещё не получен,
затем разрешает серверу продолжить. Финальная проверка подтверждает сохранение
цветов кода и отсутствие их на последующем обычном тексте.

## Производительность

Последний прогон, по 20 последовательных обновлений растущего Rust-блока;
таймер включает пересчёт подсветки, замену диапазона буфера и применение extmarks.

| Размер тела | Медиана обновления | p95 | Среднее вычисление syntax | Удерживаемый кеш |
| --- | --- | --- | --- | --- |
| 224 строки | 5,23 мс | 8,25 мс | 2,50 мс | 488 391 байт |
| 500 строк | 13,70 мс | 15,69 мс | 6,18 мс | 1 050 327 байт |

В каждом случае 20 обновлений вызвали ровно 20 вычислений syntax для изменённого
блока. Уже готовый пользовательский Rust-блок не перепарсивался. Кеш удерживал
две записи; новые версии хвоста заменяли прежнюю запись. Это локальный замер,
а не обещание фиксированной задержки на любом устройстве или для любого языка.

## Границы реализации

Поддерживаются самостоятельные fenced-блоки с явно указанным языком. Ограждения
видимы; вложенные Markdown-контейнеры не добавлялись. Для неизвестного языка,
отсутствующих parser/queries или превышения лимитов остаётся обычный текст.
Форматирование и чтение состояния сервера используют существующие интерфейсы.
